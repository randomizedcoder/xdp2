[`crates/xdp2-fastpath-control/src/hysteresis.rs`](../../../xdp2-rs/crates/xdp2-fastpath-control/src/hysteresis.rs) — `Hysteresis` policy tracks per-(family, proto, port) last-seen timestamps over a configurable grace window (default 60s). `record(observed, now)` refreshes timestamps; `active_at(now)` returns everyone still inside the window; `prune(now)` evicts and returns expired keys. `tick(observed, now)` is the one-shot helper most callers want — record + prune + return (active, evicted) in a single call. - [~] **S9f.** Way 5 caller-side verifier bounds (partial). [`samples/flow_dissector/flow_dissector.bpf.c`](../flow_dissector.bpf.c) — added `if (keys->thoff > 128) return BPF_FLOW_DISSECTOR_CONTINUE;` early-out and changed `if (hdr >= data_end) return BPF_DROP;` to `if (hdr + sizeof(struct iphdr) > data_end) return BPF_FLOW_DISSECTOR_CONTINUE;` so the verifier widens R(hdr).range to 20 readable bytes before the parser dereferences. With these bounds the verifier admits the IPv4 path (~150 insns) but rejects the IPv6 extension-header chain (~25,800 insns deep) with `math between pkt pointer and register with unbounded min value`. Root cause: `len = hdr_end - hdr` inside the generated `check_pkt_len` produces a scalar with no upper bound, and after several `ipv6_eh_node → ipv6_eh_node` unrolls the cumulative state explodes. **Way 5 BPF stays N/A in the matrix for IPv6-EH packets**; IPv4-only loads succeed. Fixing this requires either (a) a parser-graph variant for BPF that caps IPv6 EH iterations, or (b) a verifier-friendly bounded-iteration helper in the parser template — both larger than this round's scope. ⚠️ 2026-04-20
- [ ] **S9g.** xdp2-compiler verifier-friendly template emission — deferred follow-up, **scope expanded after 2026-04-20 experimentation**. Two distinct unbounded-scalar patterns exist in the generated/runtime code that the BPF verifier rejects when the unrolled dispatch loop covers ≥2 IPv6-EH iterations:
  1. **`size_t len = (uintptr_t)(hdr_end - hdr)`** in the generated `check_pkt_len` (template: [`src/templates/xdp2/xdp_def.template.c:53-76`](../../../src/templates/xdp2/xdp_def.template.c)). The verifier sees `len` as `scalar()` with no upper bound; subsequent `hdr + len` arithmetic inside the IPv6-EH unrolled chain trips `math between pkt pointer and register with unbounded min value`.
  2. **`return hdr - ctrl->pkt.start`** in `xdp2_parse_hdr_offset` ([`src/include/xdp2/parser.h:353-356`](../../../src/include/xdp2/parser.h)) — called from the IPv4 metadata extractor to record the header offset. `ctrl->pkt.start` arrives via stack spill as an unbounded scalar, so the subtraction's result is also unbounded; the verifier then rejects the offset write into `frame->...` arithmetic.

  **What was tried (none succeeded; all reverted):**
  - **`#define XDP2_LOOP_COUNT 4`** (cap unroll iterations) — verifier still rejects at insn ~9230 in 2nd EH iteration: `r2 += r7` where r7 is the unbounded `len`.
  - **`XDP2_LOOP_COUNT 3`** — rejection moves to insn ~5065, same pattern (verifier explores the 2-iteration EH chain even with 3 outer iterations because cumulative state from per-node dispatch).
  - **Makefile sed post-process clamping `len` to `0xFFFF` in the generated `check_pkt_len`** — fixes pattern #1, but immediately regresses pattern #2: rejection moves to insn ~6421 in the IPv4 metadata extractor where `r3 -= r2` (with r2 = `ctrl->pkt.start` from stack) is now the unbounded site. Net: regresses IPv4 in exchange for partial IPv6-EH progress. Unacceptable trade.

  **Concrete next-step plan (sequenced):**
  1. **Header helper fix first** ([`src/include/xdp2/parser.h:353-356`](../../../src/include/xdp2/parser.h)): give `xdp2_parse_hdr_offset` a verifier-friendly variant for BPF builds that clamps the result. Either inline the subtraction at the call site after a `(hdr - ctrl->pkt.start) <= MAX_PKT_OFFSET` guard, or `__builtin_assume`-equivalent via an explicit `if (off > 0xFFFF) off = 0xFFFF;` clamp. Header-only — no compiler rebuild required to test.

Re-introduce CO-RE if/when we ever need to read kernel-internal struct fields (e.g., for a future `__sk_buff` extension or a `vmlinux.h`-sourced internal). |
