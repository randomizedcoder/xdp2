# parser_tmpl -O Debug Plan

**Created:** 2026-02-16
**Status:** In Progress

---

## Hypothesis

The `XDP2_METADATA_TEMP_*` macros in `parser_metadata.h` generate extract functions with a signature that is incompatible with what the optimized parser template expects when using the 5-arg API.

### Supporting Evidence

| Parser | Extract Functions | Basic Mode | Optimized Mode |
|--------|-------------------|------------|----------------|
| `parser_notmpl` | Hand-written (5-arg) | ✅ PASS | ✅ PASS |
| `parser_tmpl` | Macro-generated | ✅ PASS | ❌ FAIL |

Since `parser_notmpl` works with hand-written 5-arg extract functions, the issue is specifically in how the `XDP2_METADATA_TEMP_*` macros generate their functions.

### Key Difference

**parser_notmpl.c** (works):
```c
static void extract_ipv4(const void *viph, size_t hdr_len, void *_meta,
                         void *frame, const struct xdp2_ctrl_data *ctrl)
{
    // Hand-written extraction logic
}
```

**parser_tmpl.c** (fails in -O mode):
```c
XDP2_METADATA_TEMP_ipv4_addrs(ipv4_metadata, metadata)
// Macro expands to generate extract function
```

---

## Debug Steps

### Step 1: Capture the Actual Error

Run `parser_tmpl -O` and capture stderr/stdout to see what error occurs.

### Step 2: Compare Generated Code

Compare the generated `.p.c` files:
- `parser_notmpl.p.c` (works)
- `parser_tmpl.p.c` (fails)

Look for differences in how extract functions are called.

### Step 3: Examine XDP2_METADATA_TEMP_* Macros

Check `src/include/xdp2/parser_metadata.h` to see:
- What function signature the macros generate
- Whether they match the 5-arg API expected by the optimized template

### Step 4: Compare with 6-arg API

Compare `parser_metadata.h` between:
- `num_args` branch (5-arg, fails)
- `nix_progress` branch (6-arg, works)

### Step 5: Check Template Expectations

Examine `src/templates/xdp2/common_parser.template.c` to see what function signature the optimized parser expects when calling extract_metadata.

## Expected Outcome

Identify the mismatch between:
- Function signature generated by `XDP2_METADATA_TEMP_*` macros
- Function signature expected by optimized parser template

Then determine if this is:
1. A bug in the `num_args` branch's macro definitions
2. A bug in the template
3. A missing update somewhere in the 5-arg API migration
