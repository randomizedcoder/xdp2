# parser_tmpl -O Optimized Mode Defect

**Created:** 2026-02-16
**Status:** Open - Deferred
**Branch:** num_args_and_nix
**Priority:** Low (core functionality works)

---

## Summary

The template-based parser (`parser_tmpl`) fails when run in optimized mode (`-O` flag). This appears to be a pre-existing issue in the upstream `num_args` branch, not introduced by the Nix infrastructure merge.

## Analysis

### What Works

1. **xdp2-compiler** builds and runs correctly
2. **parser_notmpl** (hand-written extract functions) works in both basic and optimized modes
3. **parser_tmpl** (template-based extract functions via `XDP2_METADATA_TEMP_*` macros) works in basic mode
4. Graph generation shows correct structure (5 vertices, correct edges)
5. Proto table extraction works correctly

### What Fails

`parser_tmpl -O` exits with an error. The optimized parser (`my_parser_opt`) is generated by xdp2-compiler from the template-based source.

### Root Cause Hypothesis

The issue is likely in the interaction between:
1. The `XDP2_METADATA_TEMP_*` macros in `parser_metadata.h` (which generate extract functions)
2. The optimized parser template in `common_parser.template.c`
3. The 5-arg API function signatures

The 6-arg API in `nix_progress` works, suggesting the 5-arg API changes in `num_args` may have introduced an incompatibility in the template-based metadata extraction.

### Files of Interest

- `src/include/xdp2/parser_metadata.h` - Defines `XDP2_METADATA_TEMP_*` macros
- `src/templates/xdp2/common_parser.template.c` - Optimized parser template
- `samples/parser/simple_parser/parser_tmpl.c` - Uses template macros

---

## Impact

**Low impact** - The core xdp2 functionality works correctly:
- Hand-written parsers work in all modes
- Template-based parsers work in basic mode
- Only template-based optimized mode is affected

Most production use cases use hand-written extract functions (like `parser_notmpl`) for better control and performance.

---

## Workaround

Use `parser_notmpl` style (hand-written extract functions) instead of `parser_tmpl` style (template macros) when optimized parsing is required.
