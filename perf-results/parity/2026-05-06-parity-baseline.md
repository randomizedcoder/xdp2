### PCAPs with documented findings (9 of 33)

These are real parity gaps the gate caught. Each is **a separate
follow-up triage item**, NOT a bug in the parity gate. The gate
correctly identified each as an unexpected divergence per the
current schema.

#### Findings of type A — XDP2 strict-rejects what kernel-flowdis accepts

XDP2 parsers (C and Rust) return `parse-error` on packets that
kernel-flowdis liberally accepts. This is XDP2 being **stricter
about packet validity** than kernel-flowdis, the OPPOSITE of "XDP2
goes deeper." Kernel-flowdis is liberal (accepts truncated /
partially-malformed packets); XDP2's compiler-generated dissectors
are strict (return error on validation failures).

| PCAP | accept Δ | field Δ | Reason (from JSONL inspection) |
|------|---------:|--------:|--------------------------------|
| `6to4.pcap`        |   6 |   0 | XDP2 rejects 6-of-N packets — likely 6to4 anycast variant |
| `gre-sample.pcap`  |  88 |   0 | 8 packets × 11 parsers — XDP2 rejects 8 of 40 GRE packets |
| `gre-within-gre.pcap` | 628 | 0 | Deeper nesting; XDP2 hits encap-depth limit on most |
| `ipip.pcap`        |  10 |   0 | IP-in-IP — likely a few malformed, kernel tolerates |
| `l2tp.pcap`        |  38 |   0 | Raw L2TP (vs clean l7_l2tp) — XDP2 stricter on the L2TP control-message variant |
| `tcp_sack.pcap`    | 133 |   0 | TCP SACK option-walking divergence |
| `vlan_icmp.pcap`   |   1 |   0 | Single-packet edge case |

For each, follow-up triage should:
1. Identify the specific bytes the strict parser is rejecting.
2. Decide whether the rejection is correct (truncated/malformed
   packet that should be dropped) or over-strict (reject of a
   valid edge case).
3. Either fix XDP2 to accept (if over-strict) OR add a new
   `expected_divergences` entry of the form
   *"this PCAP contains N packets that fail XDP2's strict-validate
    checks at offset O; documented by capture-file note"*.

#### Findings of type B — Tunnel inner-vs-outer not in mask scope yet

| PCAP | accept Δ | field Δ | Reason |
|------|---------:|--------:|--------|
| `gre-pptp.pcap` |   0 | 144 | GRE-PPTP variant — outer ip_proto=47 but the inner-flow heuristic doesn't kick in (PPTP-style call-id field instead of standard transport ports). |
| `vxlan.pcap`    |   0 | 700 | UDP/4789 IS in the tunnel-detection's `outer_udp_ports`; the disagreement is on packets where the OUTER flow itself differs (kernel-flowdis stops at outer UDP/4789, XDP2 follows past VXLAN's 8-byte header). The current mask handles ip_proto-based tunnels; UDP-port-based tunnels need additional `outer_layer_proto` field handling. |

Triage: extend `tunnel_detection.inner_outer_fields` masking to
honour `outer_udp_ports` consistently across both parsers — the
current implementation detects tunneling but doesn't yet apply the
field mask correctly when only the OUTER parser populates UDP
port fields and the INNER follows past them. Phase 17.D.5
follow-up.

## Comparison vs the matrix campaign

The matrix campaign (Phases 0-16) reported `100% acceptance` on
combo.pcap based on per-mode `*_ok` boolean counts. The parity
gate now adds three orthogonal verifications:

1. **Cross-parser identity:** every parser must produce the same
   output on the same packet. Caught the GRE inner-vs-outer
   issue, the thoff reference-frame mismatch (fixed in 17.B.C),
   and the rust-graph-enum IPv4-only scope gap (resolved in
   17.D.2).

2. **Strict-vs-liberal acceptance:** which parsers reject what
   the others accept. Caught Type A findings above — 7 PCAPs
   where XDP2 is stricter than kernel-flowdis.

3. **Documented-divergence enforcement:** every rejection must
   match a documented entry in `parity_scope.json:expected_divergences`,
   else it's flagged. This makes "100% parity" a verifiable,
   continuously-gated claim rather than an aspirational one.

## Reproducing this baseline

```bash
# Single PCAP — ~5-10 s
nix run .#flow-dissector-parity-check -- \
    --pcap data/pcaps/<pcap> --out /tmp/p

# Full corpus (33 PCAPs × 11 parsers × ~5 s/run ≈ 5-10 min)
mkdir -p perf-results/parity/$(date -I)
for pcap in data/pcaps/*.pcap; do
    bn=$(basename "$pcap" .pcap)
    nix run .#flow-dissector-parity-check -- \
        --pcap "$pcap" \
        --out "perf-results/parity/$(date -I)/$bn"
done
```

## Schema versioning

The schema is at `parity_scope.json:schema_version=1`. Bump on
any change to:
- field set / field types
- parser scopes
- expected_divergences semantics
- tunnel_detection mechanism

The comparator validates the version on every record and surfaces
mismatches as harness errors.
